PRODUCT / UX RESEARCH & UI PROPOSAL

让照片成为主角，
让复杂编辑保持秩序。

FrameMark 是一款本地运行的摄影边框与水印工作台。此方案不改写它强大的模板和导出能力，而是重新组织 175 个模板、EXIF、个人水印、预设与批量任务，让 Windows 的高效处理和 Android 的快速出片各自自然，并以自动跟随系统的暗 / 亮主题保持整日使用的一致性。

桌面三栏工作台 移动大预览 + 底部工具 情境化参数 可信导出 跟随系统明暗 离线本地处理
设计判断

当前问题不是“功能不够”，而是功能全挤在同一层级。新方案优先解决找模板、看效果、调参数、确认批量范围四件事。

依据：项目基线与需求文档、现有桌面/Android 界面和代码、同类产品功能对照、Material / Fluent / WCAG 规范。未进行真实用户访谈，结论属于桌面研究与专家走查。

01 / DISCOVERY

业务背景、用户与真实任务

先把产品边界说清楚，再决定界面应该服务谁。FrameMark 的价值不在滤镜数量，而在“摄影作品呈现方式”与“可复用的高质量出片流程”。

模板库卡片17568 手写 + 107 系统相机；持续检索是核心负担
可见品牌字标62自动匹配 EXIF，也可手动选择
运行平台2Windows 桌面 + Android；同一套业务心智
云端依赖0本地渲染、无账号、无后端；隐私是产品价值
导入照片 → 选择边框/厂商水印 → 调整版式与个人签名 → 预览每张效果 → 以预设复用并批量导出。
输入本地照片 + EXIF + 透明 PNG/WebP→处理Canvas 模板渲染→输出JPG / PNG / WebP / TIFF（桌面）

明确的业务边界

  • 个人使用，不以公开分发或商业授权为目标
  • 不做拼图、视频、动态边框和云端同步
  • 不伪造缺失的厂商布局、滤镜参数或品牌字标
  • “近似”与“不可接入”必须对用户诚实可见
  • JPG 是高质量重编码，不能笼统宣称数学无损
P0 / 当前核心

摄影深度爱好者

相机与手机照片都有，重视厂商版式、Logo、EXIF 和像素级视觉还原；会在电脑上精调，也会在手机上快速出片。

关键任务
找特定模板、比对原图、精调参数、保存预设、批量导出
成功标准
不变形、不重叠、EXIF 正确、输出与预览一致
P1 / 高频场景

手机摄影与社交分享者

希望一张照片迅速获得有摄影感的边框、机型参数和签名，然后保存或分享；不想理解复杂渲染概念。

关键任务
选最近模板、自动读取 EXIF、切画幅、单张导出分享
成功标准
少点按、预览大、默认效果足够好
P1 / 效率场景

有大量照片的业余创作者

一次活动产生几十张照片，需要同一设计稳定套用，同时能逐张检查横竖图与 EXIF 差异。

关键任务
多选导入、套用预设、逐张预览、批量进度与失败定位
成功标准
范围明确、可取消、单张失败不拖住整批
不扩展错目标用户。当前版本不需要为团队协作、账号体系、云素材商店或视频创作者设计。桌面端优先专业效率，手机端优先快速出片；两端共享模板、参数、预设与导出概念即可。
调研结论证据与痛点设计决策
模板发现比模板数量更重要175 卡依赖搜索、分类与长滚动；快捷区只有 6 个，缺少收藏和最近使用。代码审计首层提供“最近 / 收藏 / 全部”，保留搜索与厂商二级筛选；模板卡显示用途和保真状态。
预览必须始终是视觉中心用户最终按视觉验收，关心拉伸、重叠、边框比例与原图差异。项目验收规则桌面中央画布优先；手机预览固定在上方；原图对照、适应/100%、输出尺寸就近放置。
高级能力要保留，但不要全部平铺当前 Inspector 同屏串联画幅、版式、Logo、头像、文字和全部参数；手机长滚动明显。代码 + 截图首层只显示当前模板相关高频项；其余按“布局 / 内容 / 高级”分组，最多两级披露。
批量导出最需要确定感添加与导出入口分散，当前导出张数和“同一设计应用于全部照片”不够持续可见。界面走查主按钮写“导出 3 张”；导出前汇总格式、尺寸、命名与位置；进度可取消，失败可定位。
EXIF 缺失是正常状态，不是异常事故社交转发、裁切和二次编码可能丢 EXIF；同类工具也把自动识别与保留信息作为核心。同类产品显示“已读取 / 部分缺失 / 无 EXIF”；缺失字段可手填，不用猜测值补齐。
双端应一致，但不应同构桌面适合并行处理，手机适合单手持机和明确的主任务。平台规范桌面三栏并行；手机三根目的地 + 大预览 + 底部情境面板，而非把桌面三栏压窄。
01

导入

不知道示例图与真实照片的关系，批量入口不够聚焦。

明确“示例预览”标签；主按钮统一为添加照片，保留桌面拖放。

02

选版式

175 个相似缩略图造成视觉搜索疲劳。

最近、收藏、搜索、分类和厂商筛选形成稳定路径。

03

调整

高频滑块与几十个高级参数争夺注意力。

按任务显示相关参数，提供模板默认值与一键恢复。

04

检查

横竖图、缺失 EXIF、水印遮挡和近似状态需逐张判断。

胶片条逐张预览，异常在对应照片与字段旁提示。

05

导出

用户要确认质量、数量、位置和是否覆盖原图。

导出摘要 + 明确数量 + 进度/失败 + 文件夹或系统分享。

02 / APP BENCHMARKS

成熟 App 的高级感，来自“下一步很清楚”

拆解八款用户每天真的会打开的照片与创作 App。只采纳与 FrameMark 的“本地、单任务、摄影边框”定位相符的模式，不把社交平台或专业暗房的功能搬进来。

01
Apple PhotosGoogle Photos

原图随时能回来，用户才敢改

  • 点按照片即可对比编辑前后；编辑中提供撤销、重做和多步历史。
  • Apple 支持“拷贝编辑点”批量粘贴；Google 明确区分“保存”和“另存为副本”。
  • Google 把编辑工具分为操作、滤镜、光线、颜色，不摊平几十个滑块。

对 FrameMark原片永不被覆盖，要把这件事放在导出处明说；对照原图应从按钮升级为“按住整张画面”。

Apple 官方 · 编辑照片
02
LightroomVSCO

预设不是终点，可编辑的“配方”才是

  • Lightroom 预设分组、缩略图预览和强度滑杆；支持把选定编辑设置复制到多张照片。
  • VSCO 把 Recipe 与 Edit List 放在一起；长按单条修改可暂时禁用，撤销和清除全部都在同一处。
  • 两者都允许按住照片查看 Before，不打断当前编辑面板。

对 FrameMark预设展示要包含“来源、最近使用、当前生效”；不要只给一个 JSON 列表。参数面板也需要一份“本次改了哪些”的摘要。

Adobe 官方 · Lightroom Mobile
03
SnapseedInstagram

手机端不是缩小的桌面，而是一条清楚的流水线

  • Snapseed 用编辑栈保存每一步调整，支持 View Edits、撤销、重做和还原。
  • Instagram 固定“选择 → 滤镜/调整 → 下一步 → 说明/分享”的线性流程，被调整过的效果下方有圆点。
  • Instagram 在发布前提供替代文字；分享动作始终位于右上角的同一点。

对 FrameMark手机端只突出当前任务与一个主操作；导出是独立的最后一步，不应与模板、水印并排成一个底部 Tab。

Instagram 官方 · 调整照片
04
醒图美图秀秀

模板效率，是中国用户的默认心智

  • 醒图专业版强调“一键出大片、批量出图、多图同步、整组风格一致”。
  • 美图把批量水印、批量滤镜、预设复用作为桌面批处理的独立入口。
  • 两者都把模板放在高优先级位置，低级操作藏在模板之后，而不是先让人调参数。

对 FrameMark继续坚持“先模板、后细调”。但我们不跟进美颜、AI 消除、会员素材和社区，这些会破坏单一摄影工具的边界。

醒图 App Store 官方说明
COMMON PATTERNS

八个产品，最后只剩六条规律

好用的日常工具不是把能力全部露出来，而是把“我现在在哪、做了什么、下一步是什么”持续说清楚。

  1. 照片是主角。控件退到边缘，预览始终最大。
  2. 一次只强调一个动作。编辑时是调参，选模板时是套用，最后才是导出。
  3. 所有修改可逆。撤销、重做、恢复原图、按住对比，至少要有两种返回路径。
  4. 模板要能复用，也要能解释。预设必须看得见来源和当前生效项。
  5. 导出语义必须诚实。是否覆盖、是否保留 EXIF、是否移除 GPS、失败如何处理。
  6. 手势是加速器，不是唯一入口。每个手势操作都要有可点击替代和可见焦点。
ADOPT

FrameMark 应吸收

  • 按住整张预览看原图，而不仅是工具栏按钮
  • 持久撤销 / 重做，以及“本次调整”摘要
  • 批量范围与“同一设计用于 N 张”持续可见
  • 预设的来源、最近使用和当前生效状态
  • 导出明确声明“不修改原照片”，失败可重试
  • 键盘、焦点、替代文字与减少动态效果
REJECT

FrameMark 不应照搬

  • 社交信息流、账号、云相册和社区模板市场
  • 美颜、AI 消除等与“边框水印”无关的入口
  • Lightroom 级曲线、蒙版和色彩管理面板
  • 把模板、水印、导出做成三个并列底部 Tab
  • 用连续动画和玻璃效果替代清楚的状态反馈
THE MOST IMPORTANT FIX

不要再说“已自动保存”而不说明保存了什么

当前 FrameMark 会持久化设计与预设，但选中的照片只在本次会话中存在。成熟 App 会清楚区分“项目已保存”和“媒体已导出”，否则用户会在关闭应用后才发现照片没了。

本轮已改为“设计已保存”并补上整张画面按住对比
证据边界：以上为官方帮助文档与公开产品功能拆解，不等于对这些产品全部体验的背书；没有进行竞品用户访谈。吸取的是信息架构与状态原则，不复制品牌视觉、文案或独家素材。
03 / CRAFT SYSTEM

高级感来自系统，不是皮肤

参考 Linear 的安静高密度、Vercel 的排版与单色克制、Stripe 的信息密度和细节反馈，拆出能落到 FrameMark 的规则。明暗不是两套审美，而是同一语义层的两种亮度。

01

排版承担层级

一套无衬线家族、最多三档正文尺度、数字使用等宽。层级来自字号、字重和留白，而不是每个区域都加边框。

Linear / Vercel
02

安静的高密度

信息占画面，装饰退后。保留紧凑的控件与换行节奏，但去掉无意义的渐变、发光和“卡片套卡片”。

Calm density
03

只允许一个强调色

金色或砖红只用于主操作、当前项、关键状态。普通选中不靠彩色填充，改由表面层级和结构提示。

One accent
04

用表面分区，不靠描边

先通过画布、面板、浮层的亮度差建立层级；只有需要表达边界和交互时才出现 1px 细线。

Surface hierarchy
05

交互密度也是质感

按钮 hover、键盘焦点、加载骨架、导出进度、失败重试都要完整。只增加控件、不补状态，会显得更廉价。

Interaction-dense
06

状态先设计

空相册、缺 EXIF、模板不可接入、部分导出失败都是主流程的一部分，而不是最后补一块“暂无数据”。

Design the states
DUAL THEME / SYSTEM AWARE

同一张工作台，暗色与亮色都必须成立

暗色不是纯黑，亮色也不是把暗色简单反转。照片、白色边框、画布与控件的关系分别调校；两套模式共享尺寸、层级、交互与信息结构。

自动模式会实时响应操作系统外观，无需刷新。

SEMANTIC TOKENS

不要给两套主题各起一套变量名

组件只消费语义令牌。系统切换时替换值，不重建组件，也不让照片和边框受到颜色滤镜影响。

默认自动读取 prefers-color-scheme，系统切换时实时更新，不刷新页面。
允许手动覆盖用户可选亮色或暗色并记住选择；“自动”随时恢复跟随系统。
照片不受影响主题仅改变界面 token，不改变照片像素、ICC、EXIF 或导出颜色。
两种模式同等验收焦点、禁用、错误、导出进度、白色边框、空状态均需双模式实测。
反模式：把低对比灰字当成“高级”、把每个区域都做成浮卡、用金色或玻璃冒充品牌、亮色只是白茫茫一片。真正的克制应该让内容更快被认出，而不是更难被看见。
04 / VISUAL DIRECTIONS

四种视觉风格，选择一种继续深化

四版使用完全相同的信息架构与功能，只改变色彩、材质、圆角和字体气质。点击任一风格，后面的桌面端与手机端原型会同步换肤；D 是按 2026 年 iOS 27 的 Liquid Glass 更新单独校准的方向。

当前选择：D · iOS 27 液态玻璃型。本版以 D 为主方案深化：暗色玻璃更浅、选中更深，亮色玻璃随系统切换，透明度与高对比可调；A/B/C 保留为可切换的对照方向。

iOS 27 / LIQUID GLASS CALIBRATION

这不是简单的“高斯模糊 + 圆角”

D 风格按 Apple 在 WWDC26 公布的调整做视觉校准，同时保留 FrameMark 的照片优先原则。

模拟 iOS 27 的 Liquid Glass 外观调节；切换后观察上方 D 风格的桌面与手机玻璃层。
漫射与边界玻璃更有效地漫射复杂背景，用加深边缘和亮镜面高光建立分离，而不是只靠投影。
深色模式更浅深色玻璃比上一版更浅，选中项反而使用更深的底色；原型已按此处理底部标签。
透明度可调系统提供从超透明到完全着色；设计必须覆盖降低透明度、提高对比与“显示边框”。
自适应而非固定iOS 27 强调可调整窗口与尺寸类别；手机横屏、iPad 分栏和 iPhone 镜像都要重排。

边界说明：FrameMark 当前是 Windows / Android 应用，这里的 D 是跨平台 Web 技术实现的视觉提案，不是原生 iOS 控件复刻。若未来开发 iOS 版本，应直接使用系统 Liquid Glass 组件并让用户的透明度设置生效，而不是自行模拟后锁死外观。

LIQUID MOTION / INTERACTION DETAIL

按钮的“液态感”，来自光、形变和回弹

移动指针可以让高光跟随；按下会轻微压缩，松开按弹簧曲线回位。动效只解释操作，不做持续漂浮或装饰性呼吸。

支持键盘焦点；开启“减少动态效果”时关闭位移动画与扩散。
05 / DESKTOP

桌面端：并行工作台，而不是三列设置表

左侧回答“用什么版式”，中央回答“效果怎么样”，右侧只回答“当前要调什么”。批量照片与导出范围始终可见。

A 1440px：238 / 自适应 / 304 三栏 B 1024–1279px：模板库改抽屉 C 主工作流完整键盘可达 D 预览、照片、参数独立滚动
可交互原型：缩放支持按钮 / Ctrl+滚轮 / 双击；按住画面看原图，放大后拖拽平移；点击导出体验确认流程。

07 / INTERACTION SYSTEM

页面结构、信息层级与关键状态

高保真画面只是表层，真正可实施的方案还要说明页面归属、状态反馈和边界条件。

桌面端页面结构
工作台（默认）顶栏：预设 / 添加 / 导出
左：模板发现　中：画布 + 照片条　右：情境参数
模板库宽屏为左栏常驻；中宽屏改抽屉。搜索、最近、收藏、分类、厂商在同一上下文完成。
预设管理非模态下拉用于快速切换；模态页用于重命名、保存、导入/导出 JSON，不打断当前设计。
导出任务先摘要确认，再显示可取消进度；完成后给文件夹入口和失败列表，不强制阻塞继续编辑。
手机端页面结构
创作（根）照片预览 → 胶片条 → 版式/水印/文字工具 → 底部导出。支持半屏、收起和全屏预览。
模板（根）大缩略图双列网格；搜索/筛选保持状态；选择模板后回创作页并给出轻反馈。
预设（根）最近预设优先；显示模板、缩略图和更新时间；套用不替换当前照片与输出路径。
导出（任务层）底部全屏 sheet：设置摘要 → 进度 → 完成/分享；不作为与创作同级的长期导航项。

信息优先级 L1 · 持续可见

当前照片、模板效果、照片数量、主导出按钮、导出进度。任何页面都不应让这些信息失去上下文。

信息优先级 L2 · 当前任务

画幅、边距、文字区、个人水印位置、EXIF 内容、格式与尺寸。只在相关工具激活时出现。

信息优先级 L3 · 按需深入

全部数值参数、文件命名 token、平铺、偏移微调、保真说明、blocked 原因。默认折叠但可发现。

EMPTY / 首次使用示例可探索，但不冒充用户照片

允许直接试模板；画布外显示“示例照片”和添加按钮。首次添加后，示例状态自然退出。

METADATA / EXIF 缺失明确缺什么，允许手填

字段旁写“原图无此信息”，机型/日期等可编辑；其他照片不因此停止批量导出。

FIDELITY / 近似“近似”可点击解释

说明近似来自字体、纹理或精确边距；不把 approx 画成成功绿，也不给未验证样式标“原版一致”。

BLOCKED / 不可接入可见、可理解、不可误用

集中在“暂未接入”折叠区，说明缺少参考帧或布局能力；不提供无效导出按钮。

EXPORT / 部分失败成功与失败分开表达

“成功 8 张，失败 1 张”并列出失败照片与原因；可重试失败项，已完成文件不重复生成。

PRIVACY / 本地与 GPS隐私说明放在导出决策点

本地处理，不上传照片；默认移除 GPS，其余 EXIF 按格式能力回写，并注明平台差异。

08 / USER REVIEW

把自己当用户，这套设计到底怎么样？

以下是基于任务路径的专家走查，不是实际可用性测试分数。它能暴露设计判断的弱点，但不能替代真机试用。

一个真实任务

“我拍了 12 张日落，想统一加哈苏边框和个人签名，挑两张先发手机，其余晚上在电脑批量导出。”

我会先在意默认效果，而不是先理解 175 个模板。手机上我希望三次点按内看到可分享结果；电脑上我希望快速检查横竖图、确认 GPS 与命名，然后让批量任务自己跑。

作为用户，我会喜欢的地方

  • 打开后先看照片，不会被几十个参数吓退；默认模板可以直接试。
  • “最近 / 收藏”比重新翻 175 个模板更符合日常习惯。
  • 手机端导出写清 3 张，不用担心只导出了当前这一张。
  • 个人水印与模板 Logo 是两层概念，切换模板时不用重新上传签名。
  • EXIF、GPS、JPG 重编码和“近似”状态说得明白，出片结果更可信。
  • 桌面三栏让选模板、看画面、调参数同时发生，适合反复比较。
  • 明暗跟随系统、手动覆盖可记住，切换时结构不跳、照片不被染色，会让它更像长期使用的工具。
  • 按住整张预览就能看原图，比先找工具栏按钮更接近 Apple Photos 和 Lightroom 的手感。
  • 缩放、平移、全屏和原图对比都有鼠标与触屏入口，不会在精修细节时被固定画布卡住。
  • 参数面板收起后，预览和照片条都保留，导出固定在顶栏，适合先看效果再决定要不要细调。

作为用户，我仍会担心或不满

  • 手机上预览、胶片条、面板和导出仍很密，小屏设备必须验证收起面板后的可达性。
  • 模板名称里的“哈苏 4 / 徕卡 91”对新用户不够有语义，仅靠编号仍然难选。
  • 双端预设可复用不等于能自动同步；当前无云边界下，需要明确 JSON 迁移路径。
  • 同一设计批量套用很方便，但如果想给某一张单独改参数，现有数据模型并不支持，界面不能暗示支持。
  • 暗色界面适合看照片，但小字与次要按钮可能在低亮度屏幕上对比不足；亮色模式也要防止“白茫茫一片”丢失边界。
  • 如果最后只是“深灰 + 金色细线 + 大留白”，会变成另一套 Linear 风模板；品牌识别仍应来自照片和排版，而不是配色。
  • 目前还没有真正的撤销/重做与修改摘要，只有模板恢复；一旦连续调错几个参数，用户仍会缺少安全感。
  • 照片只在本次会话中存在。关闭前若没有导出，必须有明确拦截，而不是只显示一句“设计已保存”。
  • 按住对比与拖拽平移共用同一画面，手势边界必须真机测试；用户放大后再长按，容易以为对比失灵。
  • 导出确认多一步会更稳，但单张高频分享可能显得啰嗦，需要记住上次设置并简化。
优先级下一轮应改 / 应验证原因与验收方式
P0补撤销 / 重做与未导出退出提醒对照片编辑，可逆性比装饰更重要；关闭时明确提示“设计已保存，但 3 张照片尚未导出”，并提供返回导出。
P0真机验证手机垂直空间、缩放与返回行为至少覆盖小屏、长屏、三键导航和手势导航；双指缩放、放大后拖拽、按住对比不能互相抢手势；返回不会误退出或丢任务。
P0统一导出数量、质量文案和状态所有入口均显示相同张数与格式；单张可“按上次设置快速导出”，批量保留摘要确认。
P1给模板补充语义元数据在编号外增加“白底 / 侧栏 / 横图友好 / 社交 4:5”等标签；用真实模板数据验证，不凭空编造。
P1做一次 5 任务可用性测试导入、找模板、加水印、套用预设、批量失败重试；记录点按数、耗时、误操作和找不到的位置。
P1验证对比度、键盘与屏幕阅读器实测 token，而非凭肉眼；模板网格支持方向键，图标有无障碍名称，状态不仅靠颜色。
P2再考虑模板对比或单张覆盖只有真实使用证明“选择困难”或“单张例外”高频时才增加，避免现在扩大数据模型和认知负担。
总体判断：方向是对的，完成度约 8.5 / 10，但还不能叫“已验证好用”。

它比当前界面更清楚地区分了内容、工具和任务，也保留了 FrameMark 真正有价值的复杂度。最大风险不在视觉，而在手机空间、模板语义和高频导出步骤。先做真机走查与五个任务测试，再决定是否增加新能力；不要继续用更多功能掩盖信息架构问题。
