# 水印旋转后上下被裁切 — 证据（2026-11-14）

设备：OPPO PGEM10（`8267fe3e`），包 `com.framemark.native.dev`
（debug，applicationIdSuffix `.dev`）。照片为工程内的 `hdr2.jpg`（4:3 = 1.3333），
边框 `stock-oppo-hassel_text_style_1`（IR 引擎，相框即照片画布，
`pr = (0,0,1280,960)`，舞台上照片画框 = **1328 × 996 px**）。

为了看清裁切，证据用一枚 **512 × 512 的品红水印**（`wm-magenta-512.png`：
细边框 + 四角圆点 + `FM WM`），anchor = 居中、宽度 0.30、不透明度 100%。
品红在照片里没有同类像素，测“可见像素外接框”没有歧义。原工程的一份备份是
`project-original.json`（1000×240 白字水印、rotation 44）。

旋转值直接写进 `files/project.json` 再冷启动（App 的旋转滑杆只开放 ±45°，
±45 以外只有引擎/文档接受），每次重启后截图，再点「导出 → 保存到相册」拿
引擎出图。脚本：`run-matrix.sh`。

导出在同一角度下是完整的旋转图形（45° 时 821 × 820，正是正方形对角线尺寸

`bridge/android/src/paint.rs` 与 `engine/e4-hand/src/canvas.rs` 都把水印
`clip_rect(photo, …)` 后绕 dst 中心 `rotate(angle)` 绘制，没有 AABB 裁切。

## 2. 运行期几何（仪器化日志，`geo-all.log`）

舞台 1328 × 1297，画布/照片画框 1328 × 996，`aspect = 4/3`，
`rect = (0.35, 0.30, 0.30, 0.40)`（398.4 × 398.4 px 的方块）。旧 `aabb()`：

| 角度 | 旧 aabb（归一化 x,y,w,h） | 旧裁切框 px | 正确旋转 AABB px | 旧框欠高 |
| --- | --- | --- | --- | --- |
| 0° | 0.3500,0.3000,0.3000,0.4000 | 398 × 398 | 398 × 398 | 0 |
| 15° | 0.2861,0.2777,0.4278,0.4446 | 568 × 443 | 488 × 488 | 45 |
| 30° | 0.2368,0.2705,0.5265,0.4589 | 699 × 457 | 544 × 544 | 87 |
| 45° | 0.2054,0.2790,0.5893,0.4419 | 782 × **440** | 564 × 564 | **124** |
| 60° | 0.1941,0.3026,0.6119,0.3949 | 813 × **393** | 544 × 544 | **151** |
| 90° | 0.2333,0.3875,0.5333,0.2250 | 708 × **224** | 398 × 398 | **174** |

数值对得上实测：45° 时舞台只显示 532 × 440（宽 = 旋转后可见宽度，高 = 裁切框
高 440）；90° 时舞台只剩 217 × 134。

**根因（两层）**

1. `aabb()`（以及 `rect()` 里同一段旋转算式）把归一化高度当成
   “`h · aspect` 个宽度单位”。照片画框在宽度单位下是 `1 × 1/aspect`，
   所以旋转包围盒应是

   ```
   bw = |w·cos| + |h·sin| / aspect
   bh = aspect·|w·sin| + |h·cos|
   ```

   旧式子是 `bw = |w·cos| + |h·aspect·sin|`、`bh = (|w·sin| + |h·aspect·cos|)/aspect`：
   宽度方向错乘了 `aspect`（应为 `1/aspect`），高度方向的 `w·sin` 项错除了
   `aspect`（应为乘）——宽被高估、高被低估，比例都是 aspect² 的倒数关系，
   所以只有上下被裁、左右反而“宽裕”。

2. 内层图片 Box 用的是 `Modifier.size(...)`，会被外层裁切框的约束**压缩**：
   90° 时裁切框只有 224 px 高，398 px 的图片先被压成 224 px 再被裁，
   于是出现 217 × 134 的“半张图”。⇒ 内层改用 `requiredSize`。

## 4. 边界 / 手势回归

* **不出照片画框**：anchor=右上、宽 0.47、45° 时截图为
  `after-edge-45-anchor2.png`；品红像素在照片框外的数量 = **0**
  （画框 `x 56…1383, y 519…1514`，品红最外沿距上/右各 24 px）。
* **拖动仍工作**：rotation 0°（`after` 构建）从 (620,960) 拖到 (720,960)，
  项目 `dx` 0 → 0.0536（100 px 减去 32 px 触摸 slop ≈ 68 px / 1328），
  截图 `after-drag.png`。
* **九宫格热点仍映射同一格**：点「水印位置：左上」后 `anchor` 2 → 0，
  水印移到左上格且完整，截图 `after-anchor-tl.png`。
* 已知的既有行为（本次未改）：水印层在 `graphicsLayer(rotationZ)` **之内**接收
  指针事件，45° 拖动时位移按旋转后的局部轴计算（屏幕 (-200,+100) 落到
  dx/dy ≈ (-0.045,+0.18)，即旋转 -45° 后的方向）；手指落进某个 44 dp 九宫格热点
  时该次拖动被热点手势吃掉。两者在修复前同样存在。
